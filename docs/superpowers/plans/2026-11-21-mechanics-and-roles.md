# Механики партии и новые роли — план разработки

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Поправить ход партии (первый круг, балаган, прощание, видимость ролей), сделать ночь понятной ведущему (блок проститутки, итог с несколькими событиями, объявление утром) и добавить пять ролей: охранник, журналист, мясник, маньяк, бронежилет.

**Architecture:** Три этапа, каждый оставляет приложение рабочим. Этап 1 — правила партии в настройках сессии и ход дня. Этап 2 — итог ночи как список событий и утреннее объявление. Этап 3 — роли как записи справочника с новыми видами действий и опциями. Журнал событий остаётся источником истины, состояние выводит `deriveState`.

**Tech Stack:** как в проекте: Vite, React 19, TypeScript, Vitest + Testing Library, ESLint.

**Spec:** `docs/superpowers/specs/2026-11-21-mechanics-and-roles-design.md`; основная — `2026-11-14-mafia-host-design.md`, свои роли — `2026-11-15-custom-roles-design.md`. Макеты: `docs/design/mockups/` — `SetupRules`, `NightBlocked`, `JournalistStep`, `NightResultMulti`, `MorningAnnounce`, `Day1Closing`, `CardStates`.

## Global Constraints

- Вне `src/engine/roles/` нет строковых литералов идентификаторов ролей и сторон (`tests/engine/purity.test.ts`). Новые роли, их опции и стороны описываются в справочнике; экраны рисуют их по описанию.
- Движок чистый: без React, DOM, часов, случайности и хранилища. Случайный выбор начинающего делает `store` через `env.randomInt`.
- Каждая строка интерфейса — в `ru.ts` и `uk.ts` под одним ключом. Мясник по-украински — «різник».
- Игры, сохранённые до обновления, открываются и доигрываются по прежним правилам; мусор в хранилище не роняет приложение.
- Подсказка не решает за ведущего: любое событие итога ночи снимается и добавляется до подтверждения; ограничения на цель — предупреждение с «Записать всё равно», не запрет.
- Тест раньше кода, сначала падает по ожидаемой причине. `npm run check` перед каждым коммитом, коммит после каждой задачи, ничего не пушить без просьбы заказчика.
- Поведение — по спецификации, внешний вид — по макетам. Вопрос о правилах без ответа в спецификации — остановиться и спросить.

## Review Focus

1. **Старые сохранения.** Сессия без новых полей `rules`, запись подтверждения ночи с одним номером вместо набора, игра без `roleOptions` — открываются, итог прошлых ночей читается как раньше. Тесты — задачи 1.1 и 2.1.
2. **Отмена и правка задним числом.** «Отменить» после подтверждения ночи с тремя выбывшими возвращает всех троих, жилет и молчание; правка записи прошлой ночи не меняет статусы молча. Тесты — 2.1, 3.4.
3. **Статус меняется посреди шага.** Охранник, маньяк или жертва выбывают вручную посреди ночи или дня: итог, очередь круга и число голосующих пересчитываются, шаг не перескакивает. Тесты — 3.3, 3.5.
4. **Несколько ролей на одного игрока за ночь.** В одного стреляют мафия и мясник, его лечит доктор и защищает охранник; маньяк вторым визитом приходит к игроку в жилете. Ожидание — по порядку раздела 5.5 спецификации. Тесты — 3.2–3.5.
5. **Видимость ролей.** Утреннее окно, метка «молчит», «жилет снят» и красный блок не выдают роли при скрытых ролях сверх того, что знает весь стол. Тесты — 1.4, 1.7, 2.3.
